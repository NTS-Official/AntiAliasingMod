# 第五阶段：粒子、天气与世界透明效果时域处理完整方案

状态：功能已接入，待用户固定设置观察。本文定义第五阶段的架构、支持范围和数据契约。源码已接通身份／几何捕获、独立历史、原绘制顺序与原版六目标透明合成及设置；验收以第 14 节的实际视觉表现为准，已有检查记录见第 15 节。

第四阶段已在其声明范围内通过工程检查和用户目视验收；用户明确排除了尚未接入的粒子与天气。第五阶段在保留该结果的基础上，为这些内容建立可实际消费的运动信息、独立历史和透明合成路径。仅添加拒绝遮罩、仅增加诊断计数，或把所有效果移到 TAA 之后，都不能视为本阶段完成。

关联文档：[总实施方案](AA_IMPLEMENTATION_PLAN_ZH.md)、[第四阶段时域采样方案](TEMPORAL_SAMPLING_PLAN_ZH.md)、[现有逐物体运动向量方案](OBJECT_MOTION_VECTORS_PLAN_ZH.md)。本文中的类名、附件、参数和状态描述最终设计，当前落地与验证范围以第 15 节为准。

## 1. 最终目标与范围

第五阶段的目标是：世界背景与效果各自按正确运动积累历史，再按当前帧的可见性、原版透明排序和混合规则合成。移动烟雾不能拖动背景，消失的粒子不能继续残留，雨雪不能因为只有面片运动而漏掉纹理图案运动。

| 内容 | 本阶段最终处理 | 完成条件 |
| --- | --- | --- |
| 原版四边形粒子，包括破坏碎屑、烟雾、火花、爆炸等 | 实例身份、实际渲染帧状态、billboard 四角对应；不透明／镂空参与世界历史，半透明参与所属效果层历史 | 可靠区域实际消费历史；出生、死亡、切帧、旋转、缩放和遮挡正确处理 |
| 原版特殊粒子组，例如物品拾取和模型式粒子 | 根据实际提交类型关联拥有者和几何；复用模型／烘焙几何适配；不可对应部分显式拒绝 | 不因绕过 `SingleQuadParticle` 而遗漏，也不重复捕获 |
| 雨和雪 | 稳定天气列身份、几何变化、UV 图案运动、强度／覆盖变化及独立天气历史 | 相机移动、纹理循环、雨雪切换、屋顶与天气启停无错误跨帧匹配 |
| 原版云 | 世界锚定几何与云层平移、网格重建版本及云层历史 | 不把移动云当静态天空；快／精细云模式切换正确失效 |
| 世界中的火焰、拴绳和文字 | 火焰动画与覆盖响应、绳索稳定分段对应、深度测试文字的拥有者／字形对应 | 有明确接入和拒绝策略；不把独立 UI 或透视文字卷入世界历史 |
| 水、玻璃、透明实体和物品 | 保持原版透明合成位置；可对应部分提供运动，其余提供有效性与覆盖信息 | 与粒子、雨雪和云前后交错时不改变原版排序语义 |
| 模组渲染器 | 内部适配契约；标准路径可复用，未知路径保持当前帧或明确降级 | 未验证的 GPU 蒙皮、折射、自定义混合不能被标为精确支持 |

目标环境为 Minecraft 26.2、Fabric 与 NeoForge、原版及 Sodium、安装 Iris 但关闭光影。用户已验证基础 AA 在原版 Vulkan 和 Sodium + Vulkan 下可运行，第五阶段新增效果路径仍需独立验证；不能因 Iris 在该后端未启用或不提供 API 而拦截原版路径。开启 Iris 光影时 TAA 继续暂停；光影内部历史协作、TAA + SSAA 和时域升采样不属于本阶段新增能力。手持物品、HUD、GUI 和原版 always-on-top 内容继续在世界解析之后绘制。

## 2. 原版渲染事实与透明算法契约

### 2.1 已核对的 26.2 路径

- 普通粒子：`QuadParticleGroup.extractRenderState → SingleQuadParticle.extract → QuadParticleRenderState.add → QuadParticleFeatureRenderer.prepareGroup / executeGroup`。提取后以数组存储位置、旋转、尺寸、UV、颜色和光照，不能到最终顶点阶段再猜粒子身份。
- 天气：`WeatherEffectRenderer.extractRenderState / render`。雨雪由按世界列生成的四边形和滚动 UV 表现；不是一组可直接复用实体身份的独立雨滴对象。
- `LevelRenderer` 先执行主绘制、云和天气，再执行透明后处理，最后添加 `addAlwaysOnTopPass`。第四阶段在后者之前解析已经混合的主颜色；第五阶段需要提前取得未混合输入，并改为构建完整解析子图。
- 透明合成启用时，原版创建 `translucent`、`item_entity`、`particles`、`weather`、`clouds` 五个临时目标，加上 `main` 共六个输入。是否启用以当帧实际 `useShaderTransparency()` 和可用后处理链为准，不能只按画质预设名称判断。
- 透明粒子的深度行为不能统一假设为“不写深度”；当前粒子管线保留默认深度状态，天气则有写深度与不写深度两个管线。适配必须保存实际管线状态。

### 2.2 原版顺序无关透明的兼容定义

当前 `assets/minecraft/post_effect/transparency.json` 和 `shaders/post/transparency.fsh` 实现的是按目标汇总后、逐像素按深度排序的透明合成。每个目标内部可能已经混合了多个表面；它不提供任意数量透明片元的完整链表或逐片元排序。

必须保留以下算法语义：

1. 主颜色作为 alpha 为 1 的初始层，主深度使用当帧真实值。
2. 按 `translucent → item_entity → particles → weather → clouds` 的顺序插入非零 alpha 的目标。
3. 深度从小到大稳定排序；在当前反向 Z 下为从远到近，相等深度保持原插入顺序。
4. 目标颜色按预乘贡献使用：`result = result * (1 - sourceAlpha) + sourceRgb`，不能再给 `sourceRgb` 乘一次 alpha。
5. alpha 为 0 的目标不插入；最终主输出 alpha 为 1。

第五阶段保留原版后处理链作为最终六目标合成器，只替换它的输入视图为时间解析后的颜色及与之对齐的当前深度。不能把六个目标先合成后再用一个运动向量解析；不能固定“天气覆盖粒子”或“粒子覆盖玻璃”；不能用加权平均透明近似静默替代原版算法。

资源包替换透明后处理、目标布局变化或第三方替换算法时，兼容提供者必须重新核验输入及 alpha／排序契约。无法证明等价时报告 `composition_contract_unsupported`，保留该环境的原生合成并使用第 11 节降级，不强行套用默认六目标协议。

## 3. 总体架构

```text
AntiAliasingController / TaaMethod
  ├─ TemporalFrameContext       同一主视图、帧、epoch、矩阵、jitter 与配置
  ├─ TemporalSceneBridge        原版绘制边界、临时目标及 framegraph 依赖
  ├─ TemporalEffectRegistry     粒子／天气／云／绳索／火焰／文字适配器
  │    └─ EffectSnapshot        拥有者、表面、材质、前后几何与外观信息
  ├─ CompositionBackend
  │    ├─ VanillaSortedTargets  原版六目标排序透明
  │    └─ VanillaOrderedDraws   未启用排序透明时的原有绘制顺序
  ├─ WorldHistory              仅包含不透明／镂空世界及对应对象
  ├─ EffectLayerHistoryPool    每个合成域独立的颜色、深度、身份和历史
  ├─ EffectMotionPass          几何／纹理图案运动、可见性与对应置信度
  ├─ EffectReactivePass        当前／前帧覆盖、外观变化和运动冲突
  ├─ EffectTemporalResolve     预乘颜色与覆盖一起解析
  └─ TemporalComposition      当前可见性和原版规则合成 → 一次后锐化
```

核心边界如下：

- `TaaMethod` 负责整帧事务和统一采样；效果适配器不能各自推进 jitter 或持有独立相机时钟。
- `MotionCapture` 继续服务已接入模型；粒子和天气不伪装成实体 Submit。公共投影、顶点对应工具可以复用，捕获入口与身份源保持独立。
- “合成域”表示能够独立提取颜色贡献、覆盖与可见性的实际绘制集合。它按渲染路径定义，不等于 Java 类名或某一种效果。
- 原版排序透明中的五个目标各自是一个合成域。一个域内多种运动必须经过冲突判断，不能把所有粒子的速度平均成一条可靠向量。
- 世界历史与效果历史永远分开；最终合成颜色不再写回世界历史。效果不会通过背景历史被积累第二次。
- 所有 GPU 操作通过 Blaze3D。基础方案允许单颜色附件的多次绘制，不假设 MRT、compute、浮点原子、bindless 或特定 OpenGL 扩展可用。

## 4. 数据与身份契约

| 数据对象 | 必须携带的内容 |
| --- | --- |
| `TemporalFrameContext` | 主视图身份、帧号、世界／维度、epoch、实际前后投影与视图、相机位置、前后 jitter、尺寸、颜色语义、合成后端及资源版本 |
| `EffectOwnerKey` | 粒子实例或其它逻辑拥有者身份、世代、世界身份；禁止使用可变化的列表下标 |
| `EffectSurfaceKey` | 拥有者、子部件／分段／字形、重复提交序号、材质与拓扑版本；稳定对应的实际表面 |
| `EffectSnapshot` | 本次实际绘制的几何或重建参数、UV／纹理帧、颜色、alpha、发光与混合规则、可见性输入及可靠性 |
| `TemporalLayerInput` | 当帧原始颜色／覆盖、真实深度或独立效果深度、所属坐标系、合成域标识、framegraph handle、区域及生命周期 |
| `EffectMotionSample` | 当前原始 UV 到前帧原始 UV 的位移、预期前帧效果深度、对应有效性；必要时区分几何运动和纹理图案运动 |
| `EffectReactiveSample` | 实际覆盖、外观响应性、运动／身份冲突、局部可消费历史的信任度；不是单个布尔开关 |
| `LayerHistory` | 未锐化的独立层颜色／覆盖、前帧原始颜色、身份／信任度与前帧效果深度、所属帧和 epoch |

CPU 上保存完整拥有者和表面 key；GPU 身份采用有界 token 表，不直接把对象哈希当唯一 ID。基线可用 RGBA8 的 RGB 三字节无损编码 24 位 token，A 存信任度；0 为无覆盖，所有读取使用 nearest／texelFetch，禁止颜色空间转换或混合。token 在仍被历史引用时不复用；耗尽时更换世代并使对应历史失效。整数格式只有在设备能力验证后才能替换该编码。

前帧状态来自上一次成功提交的渲染帧。`xo/yo/zo`、`oRoll` 和游戏 tick 只用于重建本次实际绘制状态，不能直接当作上一渲染帧快照。渲染帧间隔、暂停、低 TPS／高 FPS、帧失败均需要独立处理。

前后位置与矩阵只进行一次 jitter 修正：运动记录在原始采样网格；历史颜色位于未抖动输出网格。历史深度／身份若保留原始网格，读取前帧原始 UV；读取历史颜色时才减去前帧 jitter。禁止在颜色、深度和身份之间混用两种坐标系。

## 5. 渲染数据流与两个透明后端

### 5.1 共用 framegraph

```text
FRAME_PREPARE
  → 冻结配置与兼容能力，预留整帧资源
  → 提取实际状态并收集身份；注入统一世界 jitter
  → 原版不透明／镂空绘制，含对应粒子
  → 保存干净世界颜色／深度
  → 按原版管线绘制透明内容，保存合成域和真实深度关系
  → 生成对象／效果运动、覆盖与响应性
WORLD_RESOLVE 子图
  → 世界历史解析，暂不锐化
  → 各合成域独立历史解析
  → 对齐当前深度与解析颜色
  → 原版排序透明或原绘制顺序合成
  → 一次后锐化，写回主颜色
  → 提交所有成功历史与拥有者快照
  → always-on-top、手持物品、后续屏幕效果与 GUI
```

`WORLD_RESOLVE` 保留为算法的逻辑解析阶段；`TemporalSceneBridge` 增加不透明快照和透明目标收集的内部接入点。现有仅接收主 `RenderTarget` 的解析入口需要扩展为声明 `OPAQUE_COLOR`、`OPAQUE_DEPTH`、`TEMPORAL_LAYERS` 和 `COMPOSITION_CONTEXT` 等输入的子图构建接口，不能在原第四阶段合成后钩子里倒推出不存在的干净背景。

所有原版临时目标都通过 framegraph 读依赖延长到对应解析结束；历史需要的内容在目标释放前复制到自有资源。不得跨帧保存原版临时 RenderTarget 或 ResourceHandle。主目标对象身份保持稳定；最终只写回颜色，不把历史深度覆盖到原版后续使用的深度。

### 5.2 原版排序透明启用

每个透明目标保存自身颜色历史和自身深度／身份。主目标中的不透明基底独立解析；如果有透明内容原本直接写入 `main`，必须按第 5.3 节提取该贡献，再重建 `main` 输入，不能重新混入背景历史。

各域在未抖动输出坐标上解析颜色。另生成与输出像素对齐的**当前帧**排序深度视图：从相应原始目标按 `outputUv + currentJitter` 读取，深度和身份用确定的离散支持点，不线性混合不同表面深度。颜色重建的支持区域必须与这些元数据相容，边界冲突进入拒绝路径。

原版后处理链读取这些临时替代输入，沿用第 2.2 节的六层稳定排序和预乘混合，结果写入独立合成输出再复制到主颜色。深度只决定当前排序，不做时间平均；不能用前帧深度、历史层序或粒子类别固定排序。原版两遍后处理不能再对已合成结果执行第二次。

原版每个目标内已经混合的多表面近似保持可识别：本方案改善其时域稳定性，但不宣称把原版六目标算法升级成无限层逐片元 OIT。不同运动在同一目标相交时使用第 8 节的冲突拒绝，不以错误的单向量强行积累。

### 5.3 未启用原版排序透明

保持原版实际绘制顺序。按连续且可独立表达的混合区间创建合成域，域身份由渲染阶段、输出目标和稳定批次语义确定，不根据当帧排序名次分配历史。

区间的插入、消失或顺序变化不因列表下标移动而清空其它稳定区间。历史按区间键、连续成功帧及逐像素表面对应验证；合成仍严格跟随当帧实际区间顺序。区间自身缺席、材质身份变化或表面无法对应时，沿用相应的帧间断／身份拒绝策略。

对标准 alpha-over，一个区间可表达为 `output = contribution + transmittance * input`。在透明底色目标中按原顺序重放冻结的绘制数据，提取预乘贡献与覆盖；深度测试使用该区间真实入口深度的快照，区间内按原深度写入规则执行。后续区间的入口深度来自原生当前帧流程，不能统一替换成只有不透明物体的深度。

RGBA8 原生目标会在每次混合时舍入，拆分后的预乘贡献再次混合可有少量数值差异。按目视验收要求，合成直接沿用原顺序和混合规则；取消为补偿这种舍入差异增加的入口颜色复制、当前帧参考重建、差值绘制及复制。入口深度和最终输出失败恢复继续保留；独立颜色／alpha 历史只保存对应层的贡献。

最终以相同区间顺序在稳定世界背景上合成。加色区间保留自己的混合类型和源系数；其衰减为 1，不能用普通 alpha-over 错误遮暗背景。会读取目标颜色、使用未知折射或不可重放状态的区间不满足该契约，必须显式降级。

若粒子与玻璃绘制交错，就按真实交错拆分区间，不能为了少分配目标而把所有粒子集中到最后。适配器仅重放已提取的绘制参数，不重新 tick、随机生成或推进粒子动画。

两个后端都需通过“历史权重为零”的原版对照。原版排序透明开关、后处理资源版本或后端变化时重建所有域并清空相应历史，不沿用旧布局。

## 6. 各效果适配器

### 6.1 普通与特殊粒子

在 `QuadParticleGroup` 调用每个粒子提取时绑定拥有者，把 token 和元数据同步传入 `QuadParticleRenderState` 对应存储位置；按 layer 分组、剔除和批处理后仍保留同一对应关系。`QuadParticleFeatureRenderer` 使用这些数据生成实际颜色及效果运动，不能依赖实体 VertexConsumer 包装器恰好覆盖粒子专用格式。

保存前后实际位置、旋转 quaternion、尺寸与四角局部坐标，重建上一帧 billboard，包括相机朝向造成的面片旋转、粒子自身 roll、缩放和特殊朝向。当前四角到前帧四角的齐次坐标通过透视正确插值后再除以 w。

纹理动画不等同于几何移动。粒子切换 sprite、改变颜色或淡入淡出时保留可证明的几何对应，同时提高响应性；无法证明图案对应的区域拒绝外观历史。出生、死亡、离开可见范围再返回、世界更换与对象复用不能串用旧 token。

粒子类型枚举按原版注册渲染组核对：四边形、模型式／拾取式、自定义和无绘制组都要有明确处理。模型式粒子适配器关联粒子拥有者再复用现有模型工具；同一几何只能注册一次有效运动来源。无绘制组不分配附件。

### 6.2 雨雪

天气列 key 使用世界／维度、世界 XZ 列坐标和降水类型。列列表顺序、相机周围索引、随机数对象地址都不能充当持久身份。

保存当前实际列端点、朝向、UV 偏移、随机种子派生结果、光照、强度和相机插值状态。面片随相机位置改变方向或裁切范围时重建前后几何；只有落在前后有效高度交集且可见的表面能够复用。

雨滴和雪花的对应按纹理图案计算。对当前片元求局部纹理坐标，在前帧同列的 UV 映射中求同一图案的位置，再投影为前帧 UV／预期深度。规则平面可以解析反解，退化映射、超出列范围或相位不连续时拒绝。不能直接把 UV 差当屏幕 UV 差。

保存未回绕时间／相位或解析出的连续相位差，正确处理原版 `% 32`、tick 掩码和纹理周期；不能只对回绕后的数值相减，也不能在跨越多个周期时猜“最短差值”。随机结果由稳定列种子和实际时间重建，不能再次推进共享随机状态。

雨雪切换、天气强度变化、屋顶和高度图变化、新列进入、视角跨列、传送与暂停恢复分别产生外观响应或局部失效。天气层的深度来自实际效果面片及原输出目标，不能用背景深度作为雨滴前帧深度。雨点落地溅起的粒子走粒子适配器，避免与天气列重复计入。

### 6.3 云、绳索、火焰与世界文字

- 云：根据原版实际云平移和相机偏移重建前后世界位置；使用稳定网格坐标、表面与重建世代标识。云质量、颜色／形状资源或网格拓扑改变时更新外观响应或历史世代。云单独拥有深度和历史，即使背景是深度为 0 的天空也不跳过云解析。
- 绳索：以拥有者和稳定分段标识对应前后实际分段顶点，包含两端移动与弯曲变化。分段数／拓扑变化使对应失效，不用实体中心速度代替整条绳索。
- 火焰：跟踪面片几何、所属对象和实际动画帧，利用 alpha 覆盖及外观响应限制历史。几何稳定不代表火焰纹理静止；不承诺无对应信息的动画 texel 精确运动。
- 世界文字：对参与世界深度测试的字形按拥有者、文本版本、字形和绘制层匹配。字体资源、文本和布局变化局部失效。`SEE_THROUGH` 显示文字及名称标签仍在原版 `executeTranslucent` 阶段绘制，保留原位置、混合和遮挡规则；不生成字形历史对应，相关贡献仅使用当前帧并去 jitter，不移到最终解析之后。真正的 `alwaysOnTop` 提交在解析之后使用未抖动投影绘制，独立 UI 不进入世界历史。
- 水、玻璃及透明实体：作为排序参与者保留真实输出目标、深度与混合规则。静态几何可用相机对应，动画纹理有独立响应；实体复用现有几何运动。FRAPI／Sodium 扩展网格只有覆盖时仍标为对应无效，不因进入独立层而宣称新增精确顶点支持。

## 7. 独立历史与颜色约定

标准 alpha-over 层保存预乘颜色 `P = alpha * color` 和覆盖 `alpha`，背景不进入该层。颜色域继承当帧原版目标和混合语义；当前 RGBA8_UNORM 路径不能未经证实就当作 sRGB 自动解码，也不能只对粒子做 gamma 转换而使其与背景不一致。颜色格式／域改变必须失效。

历史解析使用同一个最终权重混合 `P` 和 `alpha`，在同域有效邻域约束预乘颜色与覆盖，避免透明边缘黑边、亮边及颜色和透明度错位。alpha 接近 0 时不通过除法恢复任意大的直通颜色；需要直通颜色比较时使用安全阈值并限制可信范围。加色效果使用专用贡献语义，不套用 `rgb <= alpha` 约束。

历史有效性需要同时满足连续成功帧、相同世代、可靠表面对应、预期深度、当前可见性和合理外观变化。历史颜色重建对身份／深度边界做逐 tap 检查，不能双线性混入相邻另一粒子后才检查一个中心 ID。若同一表面在前帧改变合成域，只有存在明确等价域映射时才能迁移，默认局部清空。

背景仍使用第四阶段的采样误差容忍与历史约束；效果层根据自身 alpha、外观签名和局部统计判断。不能把世界颜色的固定 reactive 阈值原样套到淡烟和加色火花，也不能通过全局提高世界历史权重掩盖效果抖动。

原版深度排序始终使用当前深度；时间混合只作用于层的颜色和覆盖。世界及各层保存的历史都是未锐化结果，最终世界合成后仅执行一次现有可调后锐化。强度 0 保持恒等，锐化结果不反馈到任何历史。

## 8. 遮罩、同层多运动与消失处理

新增独立响应性／覆盖附件，保留现有运动纹理的三态语义。遮罩从实际纹理 alpha、顶点 alpha、裁剪、雾和深度可见性生成；不能用粒子四边形包围矩形代替可见覆盖。

代理覆盖沿用原生 fragment shader 的取样通道与裁剪顺序。原版粒子／天气、文字及文字背景的固定 `0.1` alpha 裁剪不能只从不存在的 `ALPHA_CUTOUT` define 推断；灰度字形以纹理红通道作为覆盖，文字背景只用顶点 alpha。实体／物品的 `ALPHA_CUTOUT` 在乘顶点 alpha 前检查纹理 alpha，其它已接入管线按各自原生顺序处理；等于阈值的片元保留。原版 `apply_fog` 保留 alpha，不另用雾距离删减覆盖。运动、身份、拥有者分组和冲突统计共用这份覆盖规则。

每个域先选出与当前可见代表表面一致的运动和身份，再统计其它有效贡献的覆盖、深度跨度、运动分歧及身份冲突。代表运动可由实际贡献及深度决定，但不能把不同速度加权平均后标为精确对应。发生明显冲突时降低或拒绝该像素的域历史；背景自己的历史继续有效。

透明模型另保留当前帧的拥有者分组，与逐面的历史 token 分开。身份和拥有者附件以运动 pass 选出的同一份代表深度做硬件 `EQUAL` 测试，不能用深度容差让后面的另一面覆盖代表身份。同一模型中，只有当前与前帧对应均可靠的表面可以共享一致运动；仍逐像素检查运动分歧，形变／视差不能因同属一个模型而跳过。不同模型、无拥有者声明和不可靠表面继续检查身份与深度跨度；历史重建始终核对原来的逐面 token，不把同一模型的不同面混作同一历史身份。分组 ID 仅在当前 pass 内分配，不进入持久历史，也不对实例身份做有碰撞的哈希截断。

该约束明确承认原版目标内部多层混合的信息限制：单个粒子或一致运动区域必须实际积累；多烟团交叉、不同速度叠加和覆盖急变区域允许保守拒绝。不能把整张粒子／天气目标永久设为拒绝，再宣称时域接入完成。

冲突拒绝必须随历史保存，不能只判断当前帧。历史身份附件保留原始采样网格中的逐面 token，并把对应不可靠或运动／身份／深度冲突的像素信任度置零；历史颜色重建逐 tap 核对该信任度。冲突消失后先提交干净的当前帧，再恢复相应区域的历史消费，避免把上一帧已经混合了其它运动的颜色重新当作可靠历史。

当前覆盖与前帧覆盖都参与消失判断。出生／死亡 token、前帧投影覆盖及当前可见性用于识别新出现和已消失内容；历史只能在仍存在的表面和当前重建支持区域内延续。粒子死亡或天气关闭时不允许仅凭旧颜色继续生成覆盖。

为 jitter／重建滤波扩展的边界范围以真实滤波核和运动为限，且进行深度约束；不能大范围膨胀到无关背景。无效区域的处理限定在相应效果层或合成域，不能让一个烟团重置整个世界的历史。

## 9. 生命周期与失败原子性

全局失效沿用模式、序列、周期、相机 cut、世界／维度、尺寸、投影、资源和 Iris 管线变化；另加入原版透明算法启停、合成目标布局、颜色语义和后端版本变化。粒子出生死亡、局部材质变化、云网格重建等优先只影响对应拥有者／域。

一帧采用统一提交事务：只有世界解析、必要效果解析、合成与主颜色写回成功，才提交新的 GPU 历史索引和 CPU 拥有者快照。缺失输入或失败帧不能只滚动其中一部分；下一有效帧检查连续性。重放颜色、生成运动和生成遮罩必须引用同一份冻结快照。

拥有者使用弱引用或显式生命周期释放；连续帧缓存不保留已死亡粒子。历史池在 OFF、世界退出、资源重载和设备关闭时释放全部纹理、缓冲、查询与域索引。原版临时目标仍归原版 framegraph 管理，不提前销毁，也不让自有池接管其所有权。

在修改原版目标前完成能力检查、管线预编译和资源预留。运行中失败时，使用保留的原生当前颜色执行一致的空间去 jitter 输出，并放弃当帧新历史；不能裸输出仍抖动的原始画面。后续帧进入明确降级／暂停状态，避免每帧失败、分配和重试。

最终写回前，在两个透明后端都已完成贡献提取后，复用贡献 scratch 保存完整原生当帧颜色，同时预编译恢复用 COPY 管线并上传其当前 jitter uniform；不新增全屏附件，正常帧增加一次全屏纹理复制。最终写回抛普通渲染异常时，先中止世界／效果事务，用该副本恢复去 jitter 当前帧，保持 `effect_output_failed` 直到已有生命周期入口重置。恢复绘制自身也失败时将异常交给控制器停用 TAA，原始异常和恢复异常一并保留；不捕获 Java `Error`，GPU 设备失效不承诺继续绘制。

不支持的目标／混合／目标读取、冻结绘制契约错误及管线异常保持失败状态，直到现有历史或资源失效入口重置。保持降级期间停止效果几何捕获、干净世界快照及效果资源初始化，原生当前帧继续去 jitter 输出。历史／捕获预算不足、暂时缺失的效果来源或合成输入允许后续帧重新评估；不能把永久能力缺失和可恢复的当帧条件混为一类。

## 10. GPU 资源、内存与性能预算

各域逻辑上独立，物理资源由池管理。当前运动和遮罩可按域顺序生成、解析并复用 scratch；已解析颜色和对应当前排序深度必须保留到最终合成结束。空域不创建历史，长期空闲域回收。

基线资源估算如下，所有数值都是设计账本，不是已测性能：

| 资源 | 设计格式／内容 | 字节／像素 |
| --- | --- | --- |
| 世界 TAA 与对象运动 | 双槽 RGBA16F＋D32 历史 24、双槽 RGBA8 原始颜色 8、RGBA32F 运动 16 | 48 |
| 每个域的历史槽，双缓冲 | 每槽：RGBA16F 解析颜色 8、D32 效果深度 4、RGBA8 原始颜色 4、RGBA8 token／信任度 4 | 每域 40 |
| 共用当前域 scratch | RGBA32F 运动 16、独立代表表面 D32 深度 4、RGBA8 响应性 4、RGBA8 当前拥有者 4、RGBA16F 贡献统计 8、RGBA16F 颜色重建 8 | 44 |
| 干净世界快照 | RGBA8 颜色＋D32 深度 | 8 |
| 合成输出 | RGBA16F | 8 |
| 原生失败恢复颜色 | RGBA8；最终写回复用已经结束贡献提取的 scratch，不另加附件 | 0（复用） |

以各域均占满屏幕估计，表内自有附件基线为 `108 + 40 * activeHistoryDomains` 字节／输出像素，不含原版透明目标、对齐、额外深度视图、顶点／uniform／query 和驱动成本，不能当作完整显存上限。五个域同时存在时为 308 字节／像素，1080p 约 609.1 MiB，4K 约 2436.3 MiB。独立代表深度用于天气等原生不写深度的效果身份选择；它不替代原生当前排序深度。第四阶段记录的 44 字节／像素属于当时单槽原始颜色的历史数据；本阶段为保证中止不覆盖已提交原始颜色而改成双槽，不能继续将旧值当作当前成本。

深度对齐和临时附件应在 lifetime 不重叠时复用；无法复用的实际资源必须加入账本，尤其是原绘制顺序后端各区间入口深度快照。非 RGBA8 原始层应提高存储格式并更新成本，不能静默压缩 HDR。Blaze3D 不支持某种独立附件用法时允许采用 RenderTarget 包装，但多出的深度纹理必须计费。

资源计划可按域的屏幕有效矩形加滤波／运动边界裁剪，记录前后矩形原点与尺寸参与坐标换算。矩形移动不能改变物体运动；越过旧矩形只局部失效。裁剪是优化，不能假设总能降低天气等全屏效果的最坏占用。

设计参数为每域身份／几何上限、全局历史内存上限和最大驻留域数；分配前检查设备尺寸、格式及预算。新增配置的设计默认值：效果时域处理启用，额外效果资源预算 2048 MiB，合法范围 128–4096 MiB。预算计算包含自有额外 scratch／视图和缓冲，世界第四阶段资源另列；实际超过预算时按第 11 节处理。4K 下五个满屏域可能触发预算降级，必须明示，不能承诺默认预算覆盖任意分辨率和效果密度。

捕获按实际批次提交并复用缓冲，避免每粒子单独 draw／uniform。新增 GPU 时间分别记录捕获相关绘制、运动／遮罩、效果解析、透明合成及总额；不能用已有 `resolveGpuNanos` 冒充整套成本。验收记录还要给出 CPU 提取／上传、平均及高分位帧时间。

## 11. 预算降级与兼容策略

| 情况 | 行为 | 历史处理与诊断 |
| --- | --- | --- |
| 单个对象首次出现、失配或外观突变 | 只使用该区域当前层内容 | 局部拒绝，不重置背景 |
| 同域多种运动无法可靠分离 | 按冲突程度降低历史权重 | `mixed_motion`，记录实际像素覆盖 |
| 域超出身份／几何预算 | 保留其原生完整当前颜色，关闭该域历史消费 | 不遗漏原本应绘制的粒子；`capture_budget` |
| 历史内存预算不足 | 按稳定优先级给域分配；其余域当前帧重建后正常参与原合成 | `history_budget`，显示哪些域未累积；采用滞后回收避免逐帧争抢 |
| 缺少可靠运动，但能提取独立贡献 | 当前层或保守响应性处理 | 不把相机重投影伪装成对象运动 |
| 未知目标读取、混合、资源包透明链或不可重放路径 | 保留原生透明路径，关闭无法证明正确的效果解析；必要时退回第四阶段路径 | `composition_contract_unsupported`，切换历史语义时失效 |
| 整帧解析发生异常 | 原生当前帧经空间去 jitter 输出，放弃新历史并进入可解释状态 | `effect_pipeline_failed`，不写入混合语义的历史 |
| Iris 光影开启 | 暂停全部 TAA，包括新效果历史 | 释放自有资源，保留用户模式，关闭光影后重建 |

域优先级依据稳定类别和资源需求，不依据瞬时帧率反复切换；预算配置变化导致的重建要明确计数。降级是资源和未知内容的边界行为，不能作为原版正常负载下主要路径的验收替代品。

Fabric／NeoForge 的加载器差异仍通过平台桥接。Sodium 的粒子、云、透明地形或批量写入替换由专门适配器核验，保留其实际输出目标和透明设置；仅仅安装成功、共享 mixin 未报错不能证明排序兼容。可选类型不能进入始终加载的核心契约。

原版透明算法、Sodium 自身透明优化和 Iris 光影内部透明算法分别判定。第五阶段要求前两者在声明版本内验证；不因此宣称支持 Iris 光影内部的 OIT／TAA。

Iris 是否参与当帧渲染必须先结合实际 GPU 后端判断。原版 Vulkan 下直接使用原版环境，不加载可选 Iris API 或执行其版本／光影输出限制；OpenGL 的真实 API 查询故障仍保留暂停保护。具体修复与基础回归见总计划第 15.7 节。

## 12. 配置与诊断

AA 模式编号、五种 jitter 序列、8／16／32 周期、后锐化和画质预设联动保持既有语义。新增效果开关和预算项在共享配置页与原版视频设置中提供，通过 Options 持久化；Fabric Mod Menu／NeoForge 配置入口共用，Sodium 继续复用共享页面。参数有独立自动隐藏重置按钮，顶部 AA 模式不加重置。

保存键约定为 `aamod_taa_effects`（布尔，默认 true）与 `aamod_taa_effect_budget_mib`（整数，128–4096，默认 2048）；缺失或非法输入恢复各自默认值。渲染线程只读取帧快照，设置回调不分配 GPU 资源；UI 区分请求启用与预算／兼容导致的实际降级。

关闭效果时域处理时，采用明确的第四阶段兼容路径并失效不同语义的历史；不得让关闭选项后仍保留额外域附件。切换采样序列等全局设置统一失效，调节锐化不重置历史。

F3 沿用原生关闭／叠加层／常显控制，增加：当前透明后端、活跃／有历史的域、粒子／天气／云对应与拒绝分类、预算降级原因、自有总内存和分段 GPU 时间。可选只读调试视图显示覆盖、运动、响应性、历史权重和透明层深度。

CPU 捕获数和身份匹配数与 GPU 历史消费分开。像素消费率需由真实解析权重统计或受控 GPU 读回提供；普通运行不做每帧同步读回。调试视图不改变采样、相机、世界或历史。

## 15. 实现进度与证据边界

以下保留自 2026-11-10 起的实现和检查记录。已增加干净世界解析、实际原顺序贡献区间、六目标合成及最终一次锐化的整帧接线，保留关闭效果选项的第四阶段路径。两种后端已有双端实际世界运行证据，当前构建待用户固定设置观察。本节早期使用的严格误差和完整组合要求仅保留为当时的检查背景；后续验收统一按第 14 节执行。

已增加的基础包括 `taa/effects/` 的弱引用实例身份、成功渲染帧快照、billboard 四角、天气列实际 UV 相位、原顶点透传捕获、批量运动／身份／冲突绘制、独立域双槽历史及预算计划；`TaaResolve` 已拆分 prepare／present／commit／abort，原始颜色双缓冲。效果开关与预算通过共享页面、原版视频设置和 Options 保存。设置回调不分配 GPU 资源。

已依据 26.2 原版字节码核对雪柱公式：`uOffset` 和 `vOffset` 都包含基于 `ticks & 131071` 的随机连续漂移，`vOffset` 另含 `-((ticks & 511) + partialTick) / 512` 下落项。雪纹对应从实际 `vOffset` 减去当前 131072 tick 周期内已经过的完整 512 tick 周期数，只解开整数回绕，保留下落与随机漂移；131072 tick 掩码断点使用独立世代拒绝旧图案。列身份仍由 XZ 和降水类型确定，不使用变化中的 UV 位模式。先前相加当前 512 tick 相位的写法会抵消真实下落，现已移除。

文字显示实体在本版本中通过 `OrderedSubmitNodeCollector.submitText` 延迟提交字形，实际字形捕获发生在 `TextFeatureRenderer.buildGroup`，拥有者由 Submit 构造时继承当前实体身份；并非在 `submitInner` 中直接绘制。已移除该外层无效文字作用域，普通背景仍使用专门的稳定几何适配，透视文字保留原透明阶段的当前帧贡献。编译器对最终 Submit 类与动态 Mixin 接口交叉类型的推断通过在提取字形数据后再读取拥有者解决，不加入运行时特殊分支。

另核对了实际 `LevelRenderer.addAlwaysOnTopPass` 和 `PreparedRenderType.drawFromBuffer` 字节码：后置阶段不会自行恢复未抖动投影，绘制时仍通过 `RenderSystem.bindDefaultUniforms` 绑定当前投影。现以 `AlwaysOnTopProjectionMixin` 包裹 `LevelRenderer.addAlwaysOnTopPass` 注册的实际世界绘制回调，只在已注入 TAA 投影的帧内，使用实际世界投影左乘逆 jitter，绘制结束在 `finally` 中恢复原投影缓冲及类型。该作用域不再包裹通用 feature dispatcher，避免介入手持物及界面的独立投影。独立投影缓冲纳入资源统计并随 TAA 失效关闭。该边界针对原版 `submitGizmoPrimitives(..., true)` 等真正的 `alwaysOnTop` 提交，不覆盖 `SEE_THROUGH` 文字；普通及透视显示文字、普通及透视名称标签均在 `executeTranslucent` 内执行。先前将透视文字描述为后置内容的结论有误；真正后置绘制已有下述 Fabric 原版 OpenGL 运行时证据，其余兼容范围不据此自动通过。

原版后置 gizmo 的几何仍在统一 feature 准备阶段生成，不能只在执行阶段处理投影。已用 `AlwaysOnTopSubmitMixin` 在原版真实后置分支标记对应 Submit，并由 `GizmoMotionMixin` 在该组准备期间暂停物体及效果捕获；普通世界组继续捕获。标记使用帧内实例身份集合，帧末清空，不按文字材质或类名猜测是否后置。

已修正效果合成失败时的提交边界：回退仅以零历史权重解析原生当前帧并输出去 jitter 结果，随后中止世界历史事务，同时清除物体历史和相机连续状态；不会再把回退后的组合世界提交为独立不透明世界历史。效果关闭时仍采用原第四阶段正常提交路径。这是运行时原子性修复，不表示全部失败点的 GPU 场景已验收。

效果预算已按配置说明与世界基础资源分开：`TaaMethod.worldAllocatedBytes` 包含世界解析、物体运动和后置世界投影缓冲；`effectAllocatedBytes` 包含干净世界快照及效果合成器，二者相加仍是自有附件／缓冲总计。合成器预算回调只计入其外部的干净世界快照，不再扣除世界 TAA 和物体运动资源。F3 同时显示世界、效果和总计，效果预算不足不会因为基础世界资源占用而提前触发整帧回退。

独立效果解析在分配运动附件和上传缓冲前计算实际新增需求，先确认该区间的历史槽与工作区能够同时容纳。准入复用既有域优先级、驻留优先和确定区间键；不能满足当前区间，或需要释放当帧仍待提交的历史时，仅拒绝当前区间，不先清空其它域。通过准入才分配运动工作区；拿不到历史槽的效果直接以原生当前帧贡献合成。帧初只为尚未创建的运动附件预留空间，已有附件不再次扣费。整帧最低合成资源本身无法满足时仍使用原有失败回退，不能把两种预算条件混为一类。

当前效果外观快照还会保存实际逐顶点 alpha。粒子、模型、方块实体、地形、文字、绳索、火焰和天气在历史对应时比较 alpha 渐变；小幅变化降低历史置信度，顶点数量或布局变化直接拒绝对应，避免淡出／消失表面继续消费旧历史。共享代码已用进程内 JDK 25 完成 Fabric／NeoForge Kotlin 编译；这只是业务修复与编译证据，不代表 E06 或第五阶段整项验收完成。

动画外观版本现按实际采样的 sprite 跟踪：`SpriteAnimationBindingMixin` 将原版动画状态关联到 `SpriteContents`，`AtlasAnimationMixin` 只在该状态完成实际图集绘制后推进其版本，不再在每次整张图集 tick 时统一推进。模型、普通粒子、火焰、原版与 Sodium 透明地形均按面片实际 UV 覆盖的动画 sprite 汇总版本；静态 sprite 不继承无关水纹或火焰的更新。地形缓存每面关联的动画内容，模型及其它动态 UV 在实际捕获时确定覆盖范围。未知或本来不可靠的几何仍保持原有拒绝语义，外观版本修复不把它升级成精确运动。

独立场景还发现上传池在请求尺寸缓慢增长时不断跳过旧页并追加恰好大小的新页，长期运行会耗尽页数。`TemporalUploadArena` 现对本帧尚未使用的不足页按容量档位扩容并关闭旧环形缓冲；本帧已经上传的页仍不覆盖。预算预测计入实际扩容差额，帧结束继续轮换已使用的三槽缓冲，关闭时释放全部页。这是实际资源生命周期修复，专用增长负载验证仍留在 TEMP。

未归属模型顶点原先只进入世界运动拒绝，未向独立透明层提供覆盖。现将 `MotionCapture` 中无可靠 Submit／局部几何对应的完整批次接入 `ModelEffects` 的不可靠捕获，保留实际材质、UV、alpha 和原生绘制来源；没有稳定对应的批次使用当帧身份、零置信度，不生成精确顶点历史或模型共同运动组。专用 `EffectQuadConsumer` 标记已由效果适配器捕获的底层消费者，避免字形等几何被重复添加为不可靠模型。此处标记只表达真实捕获归属，不是验证入口或测试开关。

### 2026-11-13 最终写回中断后的原生颜色恢复

`TaaResolve.present` 原先抛异常时直接进入控制器停用逻辑，跳过第 9 节要求的空间去 jitter 恢复。现由 `finishCapture` 在贡献提取结束后，把完整原生主颜色复制到既有 contribution scratch，并提前准备 COPY 管线和 jitter uniform、核对实际预算。`TaaMethod` 捕获最终写回异常后中止世界／效果事务，使用该副本恢复主目标，保持 `effect_output_failed`；失败帧不提交 GPU 历史、CPU 对象快照或相机连续状态。恢复再次失败时向控制器保留两次异常。正常帧只多一次颜色复制和一份对齐后的 16 字节 uniform，不新增全屏纹理、测试配置或测试入口。

独立 `%TEMP%/aamod-stage5-output-recovery` 工具在 Fabric 原版 OpenGL 标题页创建真实 `TaaMethod`，按公开接口准备并执行四帧：正常提交、最终写回中断、保持失败的当前帧回退、通过已有 `PIPELINE_CHANGED` 入口恢复。只有 TEMP agent 在第二帧进入 `present` 时把目标清成另一种颜色后抛异常；生产方法没有测试分支。工具独立读回故障前的实际原生颜色，并要求保存色与它逐字节一致；恢复输出与 CPU 双线性当前 jitter 重建对照。

针对上述掉帧，复用 `%TEMP%/aamod-stage5-normal-composition` 的隔离 Fabric＋OpenGL 混合场景，固定 Halton＋16、锐化 0、1920×1080 启动尺寸、视距 6 和原顺序透明。JFR、采集 agent 及运行目录均留在 TEMP；没有操作用户客户端，也没有新增生产测试入口。

状态：已实现，隔离 GPU／实体运行检查通过；2026-11-09 用户确认已接入部分视效正常。粒子、天气等未接入路径不在此次画质通过范围内，见第 8 节。

Minecraft 26.2 先提取实体状态，再收集 Submit，最后在 FeatureRenderer 中批量生成顶点。实体身份必须跨越这些阶段。模型由多个实体共用，不能直接把上一帧变换保存在共享 ModelPart 上。

## 2. 顶点对应和覆盖范围

按实体／方块实体实例保存历史，随提取状态和 Submit 传播。历史按提交几何、材质、模型部件及重复绘制序号隔离。从实际顶点流采集位置与最终纹理坐标，保留上一次成功解析帧的对应顶点裁剪坐标。这样同时涵盖实体平移、旋转、缩放与 ModelPart 层级动画，不用实体中心位移代替动画运动。

模型、物品、方块模型和自定义几何各有接入点。模型部件使用部件身份及局部几何签名核验对应；物品／方块模型使用实际 BakedQuad 身份；没有稳定对应的自定义几何只生成历史拒绝标记。模型／材质／拓扑改变、首次出现、离开视野后重新出现、顶点不匹配时不复用旧历史。

精确 BakedQuad 对应适用于原版烘焙路径。Fabric FRAPI／Indigo 和 Sodium 的扩展物品／方块网格可绕过该路径；本次在共享 FeatureRenderer 顶点入口补充这类几何的真实覆盖，并写入历史拒绝标记，不宣称已有扩展网格的精确运动向量。每个顶点消费者分别保存未匹配几何，避免同材质的独立顶点流被错误拼接。Sodium 下的 ModelPart 动画仍使用精确对应。

半透明物体和没有可靠顶点对应的路径采用保守历史拒绝。粒子、天气、云、文字、火焰、拴绳及其它未接入路径保留当前响应性拒绝，不能宣称它们已有精确运动向量。手持物品和 GUI 仍在 TAA 后绘制。

## 3. 运动纹理和可见性

新增原分辨率 RGBA32F 纹理，每像素 16 字节；使用完整浮点存储反向 Z 的预期前帧深度，避免半精度深度在远处精度不足。R/G 为从当前原始像素 UV 指向前帧原始 UV 的位移，B 为前帧预期深度，A 为三态：0 使用静态相机重投影、1 有效物体运动、-1 已知动态但历史无效。

在 WORLD_RESOLVE 前，用当前实际投影重新光栅化捕获的真实顶点。纹理透明裁剪、剔除和世界深度共同约束覆盖；半透明路径另检查纹理与顶点 alpha。原版不透明 shader 不因 alpha 为零而丢弃的几何保持原版语义。被墙遮挡和纹理孔洞不能写入物体向量。半透明覆盖前景时写拒绝标记。运动纹理不改世界颜色和深度，不重画实体颜色。

每个顶点携带当前位置、前帧裁剪位置、最终 UV 与有效状态；GPU 透视正确插值前帧齐次坐标，在片元阶段除以 w。不能先逐顶点除以 w 再线性插值 UV。jitter 已包含在实际前后投影中，TAA 仅在读取未抖动解析历史时减去上一帧 jitter，避免重复修正。

## 4. TAA 消费

动态有效像素优先使用物体向量的前帧 UV 和预期深度；静态像素沿用相机矩阵重投影。动态无效像素直接输出当前颜色，不错误退回静态重投影。前帧深度不匹配、越界、w 非正或非有限时拒绝历史。保留原色响应性检测、YCoCg 邻域裁剪、运动权重衰减和未锐化历史；后锐化保持显示阶段独立输出。

## 5. 生命周期、预算与诊断

模式、世界、相机、尺寸、资源、渲染管线或历史 epoch 改变时同步清理。只提交成功解析帧的几何历史；断帧后重新出现不跨帧消费旧顶点。缓存使用弱拥有者和有界顶点预算；超预算必须显式安全降级，不能默默把未捕获动态物体当作静态物体。

增加 F3 捕获顶点、有效／拒绝批次和预算状态；这些是工程诊断，不冒充逐像素历史采纳率。Iris 光影开启时 TAA 仍暂停。原版／Sodium／安装 Iris 但关闭光影是需要验证的路径；两加载器使用共享实现。

## 6. 验证和验收

1. 精确数学检查：平移、旋转、缩放、相机运动、模型部件动画和透视插值。
2. 隔离性检查：两个实体共用一个模型、同一部件重复层、出生／消失／重新可见、几何和材质变化。
3. GPU 检查：向量方向、前帧深度、透明孔洞、遮挡、无效标记，以及 TAA 对物体向量和拒绝标记的实际消费。
4. Fabric 与 NeoForge 构建、Mixin 运行检查；报告实际运行的检查与支持边界。
5. 不操作玩家观察客户端，不自动切参、截图、传送、重载、重启或退出。用户用固定设置长期观察闪烁、拖影和软化；已接入部分的确认记录见第 8 节。仅临时隔离测试客户端执行自动场景和退出。

## 7. 实际实现与工程验证记录

实现位于 `client/antialiasing/taa/motion/` 与 `client/mixin/render/motion/`。使用实际顶点历史而非实体中心速度；前帧裁剪位置保存的是上一次成功解析使用的实际投影，包含相机旋转、层级变换和 jitter。ModelPart 与 BakedQuad 的局部几何／UV 签名不同、帧不连续或 epoch 不同均拒绝匹配。自定义几何只提供拒绝覆盖，未声称精确匹配任意程序化拓扑。

前后几何按材质区分，原版纹理矩阵只在 `APPLY_TEXTURE_MATRIX` 时生效；原版层叠矩阵应用在对应裁剪坐标上。光栅化时有效批次先画，拒绝批次后画，半透明拒绝最后画，避免保守拒绝被后续有效向量覆盖。运动附件清除值显式设为 `(0,0,0,0)`，不能使用 JOML 默认 W=1 的无参 Vector4f。

每帧预算为 262,144 捕获顶点、8,192 几何批次。超预算不提交部分历史，解析权重为 0；下一成功帧重新积累。拥有者使用弱映射，清除超过上一帧的几何历史，防止已不可见但仍加载的实体无限保留缓存。

历史纹理仍为 28 字节／像素；新增运动附件为 16 字节／像素，总纹理附件为 44 字节／像素：1080p 约 87.0 MiB，4K 约 348.0 MiB。另有 CPU 几何快照、顶点和 uniform ring、query 与驱动开销。上传顶点为 48 字节／三角形顶点，四边形展开为 6 顶点；uniform 为每批次 96 字节并按设备对齐。`TaaResolve.allocatedBytes` 继续只统计历史，`MotionCapture.allocatedBytes` 单独统计运动附件；解析 GPU 时间不包含之前的运动 pass，不能用它代表完整 TAA GPU 成本。

Sodium 运行日志确认当前 `MotionVertexConsumer` 使用标准 VertexConsumer 路径，未接入 Sodium 的批量优化写入接口，并给出性能提示。该路径能正确绘制和捕获，但可能增加 CPU 顶点提交成本；本轮没有独立性能基准，不据此宣称开销可忽略。

真实消费证据：让相机重投影 UV 故意越界，物体向量仍能将当前 138 与前帧 128 混合为 134；同输入改为拒绝标记、错误前帧深度或没有物体向量时输出 138。该受控 GPU 检查证明解析实际采纳物体向量，CPU 匹配计数不充当该证明。12 项向量检查误差上限为 0.0001 UV，包含栅格插值精度；不把纹理格式的 32 位精度等同于光栅器无限精度。

最初原版运行在所有断言通过后遇到测试进程关闭看门狗（`fabric-run.log`）。临时验证入口后续在测试世界正常保存后显式退出，仅作用于测试进程；正式模组没有退出钩子。随后 `fabric-gpu-3.log` 正常成功退出。自动检查与用户长期目视验收分开，后者的确认记录见第 8 节。Iris 启用光影的 TAA 暂停策略没有扩大支持范围；本轮没有重新启动光影包做画质验收。

NeoForge 可选依赖检查的早期启动被依赖元数据警告页和首次启动无障碍引导阻塞，未进入世界，不能记作通过。仅在临时测试目录关闭加载警告页显示，临时测试入口完成引导继续进入测试世界；未关闭正式图形校验。最终结果以 `neo-iris-verified.log` 的完整断言和成功退出为准。
